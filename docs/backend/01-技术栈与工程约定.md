# 01 · 技术栈与工程约定

## 1. 技术栈

| 层 | 选型 |
| --- | --- |
| 运行时 | **Node.js ≥ 22**（`package.json` `engines` 锁定） |
| 模块体系 | **ESM**，源码文件一律 `.mjs` |
| 依赖 | **零 npm 运行时依赖（硬约束）**，只用 `node:` 内置模块 |
| 测试 | `node --test`（内置 runner），测试文件 `test/*.test.js` |
| 构建 | 无构建步骤、无转译、无打包 |

**语言与依赖是硬约束：源码只用 `.mjs` + `node:` 内置模块，`package.json` 永远没有 `dependencies` 字段。**

> 说明：`test/` 目录按存量惯例使用 `.test.js` 扩展名（`node --test test/*.test.js`），这是**唯一**允许 `.js` 的位置；新增测试文件沿用 `.test.js`，不得改成 `.mjs` 以免命令序列漏收。

## 2. 零依赖约束的判据与边界

- **判据**：`package.json` 不存在 `dependencies` 字段；`node_modules` 不存在（或仅含 devDependencies 产物）。
- 允许：`node:crypto`、`node:fs`、`node:path`、`node:http`、`node:stream` 等内置模块。
- 不允许：为「方便」引入 lodash / axios / express / undici 等任何运行时包。
- 需要新能力时**先问**（`AGENTS.md` `A3`）：要么用内置模块实现，要么用户书面豁免。
- Docker 镜像（`node:22-alpine`）同样不装任何额外包。

## 3. 命令

```bash
npm start       # node server.mjs
npm test        # node --test test/*.test.js
node server.mjs # 冷启动（HOST/PORT/UGW_* 环境变量，见 config.mjs loadConfig）
```

提交前 `npm test` 必须全绿（闸门细则见 `08-测试与验收.md`）。

## 4. 配置来源（约定）

- 环境变量只作**首次默认值**：`loadConfig(env)` / `loadSettings({ env })` 读取 `UGW_*` 与池专属变量。
- 持久配置一律落 `data/` 下 JSON 文件，**文件优先于环境变量**（`pools/settings.mjs` 头注即此约定）。
- 新增配置项三件套：`config.mjs` 或 `settings.mjs` 的默认值 + `ENV_KEYS` 映射 + 对应测试，缺一不可。

## 5. 风格约定

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 文件名 | 小写 kebab-case | `claim-scheduler.mjs`、`sse-reader.mjs` |
| 常量 | 全大写下划线 | `DEFAULT_MAX_BODY_BYTES`、`KEY_PREFIX`、`SUCCESS_WINDOW` |
| 函数 / 变量 | 小驼峰 camelCase | `sessionKeyOf()`、`quotaRatio` |
| 工厂 | `createXxx` 前缀 | `createGateway()`、`createPoolScheduler()`、`createZcodePool()` |
| 错误类 | `XxxError` + `status/type/code` 三件套 | `HttpError`、`AuthError`、`RouteError` |
| 导出 | 具名导出；模块级单例不默认导出 | `export function sendJson(...)` |

- JSDoc 注释写「约束与为什么」（如 `routing.mjs` 的「按第一个 `/` 切」），不写「下一行做什么」。
- 注释里引用文档编号（如「文档 §6 / §11」）时确认目标存在，不写悬空编号。
