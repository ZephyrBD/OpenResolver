# 03 · 上游适配层规范

## 1. 总则

**公共层（`pools/base.mjs`、`http/`、`adapters/`、`auth/`、`fingerprint.mjs`）已有的能力，池适配层必须复用，禁止手写等价物。**

优先级从高到低：

1. **公共层能力**（本节强制映射表）——默认选择
2. **同类池已实现的通用模式**（如 `autoPollOnboardBox` 对应的后端两段式流）——第二个池需要同模式时上提公共层，不允许第三份拷贝
3. **池内自研**——仅限上游私有协议（签名、加密、私有信封），且必须登记进 `09-模块清单.md`

判断口径是「能力」，不是「顺手」：`base.mjs` 能表达的调度语义，就不允许因为「这个池特殊一点」而在池内重写一套权重。

## 2. 强制映射表

| 场景 | 禁止 | 必须使用 |
| --- | --- | --- |
| 多账号选号/权重/冷却/熔断 | 池内自写权重算法或时长常量 | `pools/base.mjs` `createPoolScheduler()` |
| 粘性会话 key | 池内自造会话 hash | `pools/base.mjs` `sessionKeyOf()`（混入 keyId，防止跨密钥撞号） |
| 调度参数默认值/钳制/持久化 | 直接 `fs` 读写、内联默认时长 | `pools/settings.mjs`（`DEFAULT_SETTINGS` / `clampSetting` / `patchSettings`） |
| JSON 响应写出 | 手拼 `res.writeHead` | `http/respond.mjs` `sendJson()` / `apiError()` |
| 错误抛出 | 裸 `throw new Error` 穿到端点 | `http/errors.mjs` `HttpError`（`status/type/code`）；鉴权用 `AuthError`、路由用 `RouteError` |
| 请求体读取 | 手写 chunk 收集 + 越界判断 | `http/body.mjs` `readJson()` + `DEFAULT_MAX_BODY_BYTES` |
| SSE 解析 | 手写 chunk 缓冲拼接 | `adapters/sse-reader.mjs` `createSseParser()` |
| 协议转换 | 池内逐字段手转 | `adapters/anthropic-to-openai.mjs` / `openai-to-anthropic.mjs` |
| 设备/会话指纹 | 池内自造 deviceId 算法 | `fingerprint.mjs` `deviceIdFor()` / `sessionIdFor()` |
| `<pool>/<model>` 拆分 | 池内自行切模型名 | `routing.mjs` `routeModel()`（第一个 `/`，池名可带 `-`） |
| 落盘写入 | 直接 `fs.writeFileSync` 目标文件 | tmp + rename 原子替换（见 `06 §5`），凭证文件 `0o600` |

## 3. 池适配文件角色契约

`pools/<池>/` 内文件按角色命名，职责如下：

| 文件 | 职责 | 导出形态 |
| --- | --- | --- |
| `index.mjs` | 池工厂与组装：`createXxxPool()`，挂 `name`、调度器、chat/quota/models 能力；冷却 kind → 时长映射只引用 settings，不自定数值 | `createXxxPool({ accounts, ... })` |
| `auth.mjs` | 凭证换取与刷新（OAuth 轮询 / PAT 校验 / 回调换 token） | 纯函数或小工厂 |
| `quota.mjs` | 额度查询 + 缓存（回源节奏在池内，语义口径在 `06`） | `createXxxQuotaCache()` |
| `stream.mjs` | 流式转发：构造上游请求、透传 SSE、识别业务错误 | 挂池能力 |
| `payload.mjs` | 上游请求体构造（模型映射、参数裁剪） | 纯函数 |
| `onboard.mjs` | 浏览器接入流（登录链接 / 回调 / device 轮询），供 `panel/api.mjs` 调用 | `createXxxOnboard()` 或端点函数 |
| `checkin.mjs` / `claim.mjs` | 签到/领取：导出 `createClaimer()`，`run()` 保证不抛 | `createClaimer(...)` |
| `constants.mjs` | 上游域名、路径、版本号、魔数——**上游事实的唯一落点** | 全大写常量 |
| `models.mjs` / `models.json` | 模型元数据：`id / display_name / context_window / supports_tools / supports_thinking` | 数组 |

硬约束：

- **池名必须与调用名前缀一致**：`routing.mjs` `routeModel()` 按第一个 `/` 切，`pool.name` 直接参与 `/v1/*` 调用名（`zcode/GLM-5.3`）。改池名 = 改存量契约（`W4`），属重决策。
- **上游 HTTP 200 里可能塞业务错误信封**（zcode `{"code":1005}` 先例）。池的响应处理必须有 `businessErrorOf` 类检查，禁止只看 HTTP 状态码就当成功透传。
- 上游真实值（冷却时长、阈值）来自 `pools/settings.mjs`；池内只允许引用，不允许复制数值（`zcode/index.mjs` 的 `COOLDOWN` 注释即此约定：避免两处漂移）。

## 4. 允许池内自研的情形

> 判据：**长得像通用能力 → 上提/复用公共层。上游私有协议 → 才自研。**

真正允许自研的两种情况：

**情况一：公共层没有对等能力。**

- 上游私有签名协议（CodeArts DPoP：`dpop.mjs` / `signer.mjs`）
- 上游私有加密/编码（Qoder `cosy.mjs` / `encode.mjs`）
- 上游特殊限流策略（WorkBuddy `ratelimit.mjs`）

**情况二：上游行为偏离协议假设，公共层表达不了。**

判断方法是自问：**「我能不能只靠给 base / adapters 传参数，把这条上游规则表达出来？」** 能传参表达就传参；不能才自研，并登记 `09`。

不算理由：

- 「这个池只有一个账号，不需要调度」→ 仍走 `createPoolScheduler`（单账号权重恒定，行为一致）
- 「抓包脚本里已经写好了」→ 抓包是事实源不是实现（`00 §2.2`）
- 「先复制隔壁池改改」→ 同类模式第二次出现就该提取，见 §5

## 5. 复用义务

- **写第二个同类实现之前必查**：同池 `components`（本池文件）、`pools/base.mjs`、其它池的同类文件。已实现就提取复用，不许「先复制、以后再说」。
- 三个池都出现的模式**必须**上提公共层（如 onboard 的两段式链接流）。
- 公共层的修改属重决策（`A3`）：影响所有池，先 `F3` 给方案再动。

## 6. 新增一个池的判定流程

```
要接一个新上游
   ├─ 抓包确认鉴权流 / 端点 / 错误码（00 §2）
   ├─ 建 pools/<池>/，按 §3 角色契约拆文件
   ├─ 查 §2 映射表：调度/信封/SSE/指纹一律走公共层
   ├─ 上游私有协议部分自研 → 登记 09
   ├─ boot.mjs 组装（失败只警告，不拖垮启动——存量约定）
   ├─ panel/api.mjs 加 onboard 端点、app.js 加接入流
   ├─ test/ 补 <池>.<特性>.test.js（08 §2）
   └─ 09-模块清单.md 登记能力矩阵
```
