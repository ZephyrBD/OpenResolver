# 09 · 模块清单

> 对应前端 `docs/frontend/09-组件清单.md` 的登记制度：**公共层之外的自研能力、新增池、新端点，未登记视为违规**（`03 §4.4`）。新项目接入时按实际情况维护下表。

## 1. 池注册表（`pools/<池>/`）

登记格式：职责（上游是什么）/ 接口（导出与被调用方式）/ 特殊机制（为什么 base 不够）/ 能力矩阵。

| 池名 | 上游 | 鉴权流 | quota | claim/checkin | 特殊机制（登记理由） |
| --- | --- | --- | --- | --- | --- |
| `zcode` | ZCode（Anthropic 协议上游） | OAuth 两段式（生成链接 + 轮询入库）+ 手动 JWT 导入 | ✓ | ✓（含周末活动包抢领） | 200 内业务错误信封（`businessErrorOf`）；指纹 `fingerprint.mjs` |
| `qoder` | Qoder 国际版 | PAT 导入（device flow 已移除） | ✓ | ✓ | `cosy.mjs` / `encode.mjs` 私有编码 |
| `qoder-cn` | Qoder 国内版 | 同上，region 变体 | ✓ | ✓ | 与 global 共享实现，region 决定端点 |
| `trae` | Trae | 登录链接 + 回调 URL 入库 | ✓ | ✓ | `headers.mjs` 指纹头组 |
| `workbuddy` | WorkBuddy 国际版 | 登录链接 + 轮询入库 | ✓ | ✓ | `ratelimit.mjs` 限流策略 |
| `workbuddy-cn` | WorkBuddy 国内版 | 同上，region 变体 | ✓ | ✓ | 共享实现 + `constants.mjs` 端点切换 |
| `codearts` | 华为 CodeArts | OAuth 授权链接 + 回调 / ticket 轮询 | ✓ | ✓ | DPoP 签名（`dpop.mjs` / `signer.mjs`） |

约束：

- 池名 = 调用名前缀（`<pool>/<model>`），修改池名属重决策（`03 §3`）。
- 新增池必须在本表登记能力矩阵，并走 `03 §6` 判定流程。
- region 变体（`qoder-cn` 等）是**独立池名、共享实现**，不新建平行目录复制一份。

## 3.1 plugins/opencode/（外部插件包，豁免登记）

OpenCode 宿主的池余额 TUI 插件（`ugw-pool-balance`）。**豁免**本规范套件两项硬约束，理由：它不参与网关运行时，由 OpenCode 宿主加载。

- 依赖豁免（`01 §2` 零 npm 依赖）：其 `package.json` 声明 `@opencode-ai/plugin` 等宿主依赖，安装由宿主管理；网关本体（仓库根 `package.json`）仍严格零依赖，闸门 G-B2 不受影响。
- 扩展名豁免（`01 §1`）：`src/tui.tsx` 为 OpenCode TUI 侧 Solid 组件，宿主要求 TypeScript。

约束不变项：不 import 网关源码（只经 HTTP 调面板 API）、不读写 `data/`、改动需在本节同步登记。

## 5. 新增登记的判定流程

```
要新增一个模块（池/公共层/端点/工具）
   ├─ 查本清单与对应规范层 → 有对等能力？
   │    ├─ 有 → 复用，不重复造
   │    └─ 没有 ↓
   ├─ 回答三个问题（对应 03 §4）：
   │    1. 公共层有没有行为对等能力？
   │    2. 传参表达不了哪条上游规则？
   │    3. 将来公共层扩展后，替换成本是多少？
   └─ 实现 → 立即在本清单登记 → test 补覆盖 → 闸门（08 §4）
```
