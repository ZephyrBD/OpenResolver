# 08 · 测试与验收

> 本文对应前端规范里的「数据与状态」的工程纪律部分 + `AGENTS.md` `R6` 的后端闸门映射。

## 1. 测试体系

- Runner：`node --test`（内置），命令固定 `npm test` = `node --test test/*.test.js`。
- 现状约 70 个测试文件，按域覆盖：adapter / gateway / guard / keys / 各池 / panel / scheduler / settings。

## 2. 文件命名与结构

| 项 | 规则 | 示例 |
| --- | --- | --- |
| 测试文件 | `<域>.<特性>.test.js` | `zcode.pool.test.js`、`panel.csrf.test.js`、`settings.cooldown.test.js` |
| 上游桩 | 一律 `test/helpers/stub.mjs` `startStub(ctx, handler)`——真 HTTP 桩，记录每条请求 | 不用 `nock`、不 monkey-patch fetch |
| 网关组装 | `test/helpers/gateway.mjs` / `panel.mjs`——被测对象的组装器 | 不在每个测试里重跑 `boot()` 全家桶 |
| 静态样本 | `test/fixtures/` | `anthropic-sse.txt` |

**硬约束：测试禁止直连真实上游。** 任何上游行为都用桩表达；需要新上游样本时抓包摘录进 `fixtures/`，凭证字段一律替换为假值。

**复用义务（对应 `03 §5`）：新测试先查 `test/helpers/` 有没有现成桩与组装器；两个测试需要同一桩场景时提取进 helpers，不许第三份拷贝。**

## 3. 断言纪律

- 断言行为结果（状态码、信封结构、调度决策），不断言实现细节（内部变量名、调用次数慎用）。
- 时间相关断言用注入时钟（`createPoolScheduler` 的 `now` 参数），不 `sleep` 真等。
- 异步竞态断言：SSE/abort 类测试参考 `zcode.abort.test.js` 的写法，收尾等待连接关闭再断言。

## 4. 后端四闸门（`AGENTS.md` `R6` 的端别映射）

| 闸门 | 命令 | 绿的判据 |
| --- | --- | --- |
| G-B1 单元测试 | `npm test` | 全部 pass，无 skip、无 todo 兜底 |
| G-B2 零依赖校验 | `node -e "const p=require('./package.json'); if(p.dependencies) process.exit(1)"` | `package.json` 无 `dependencies` |
| G-B3 实跑冒烟 | `node core/server.mjs` 冷启动无未捕获异常 + curl `/v1/models`（或面板登录）返回合法 JSON | 响应可解析、无 5xx |
| G-B4 安全自检 | grep 源码与测试：无真实凭证字面量；新增 `console.log` 逐条核对脱敏 | `07 §6` 全绿 |

- 前端四闸门（类型检查/Lint/单测/浏览器实跑）与本表的对应关系：**类型检查+构建 → 由零依赖校验与 `node --test` 启动覆盖（无 TS 无构建）**；浏览器实跑仅在前端任务执行，后端任务以 G-B3 curl 实跑替代。
- 缺失项不得默认跳过：无法执行某闸门时走 `F3` 阻塞，由用户书面豁免（`R6` 细则）。

## 5. 失败处置

引用 `agents/WORKFLOW.md` §6.3 失败处置分级表，后端替换词表：

| 前端口径 | 后端对应 |
| --- | --- |
| 类型错误（公共层） | 信封/调度语义/鉴权链变更（`W2` 公共层）→ `F3` 阻塞 |
| 类型错误（局部） | 池内或端点局部逻辑修正 → 自主修 + `F1` 公示 |
| `any` / `@ts-ignore` | 无 TS；等价禁令 = 为通过测试放宽断言、捕获后吞错（`X1` / `X3`） |
| 浏览器白屏 | 冷启动崩溃 / curl 冒烟 5xx |

存量遗留失败登记进基线偏差表，不静默修掉（`X6`）。
