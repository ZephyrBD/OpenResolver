# 06 · 调度与状态规范

> 本文对应前端规范里的「布局与页面范式 + 数据与状态」：前端的问题是「状态从哪派生、谁能改」，后端的问题是「调度语义归谁维护、账号状态谁说了算」。

## 1. 调度语义单一来源（硬约束）

调度语义**只在两处维护**，池适配层与面板只读：

| 内容 | 唯一落点 |
| --- | --- |
| 权重公式、选号、冷却状态机、熔断 | `pools/base.mjs` `createPoolScheduler()` |
| 参数默认值、ENV 映射、钳制、持久化 | `pools/settings.mjs` |

权重公式（`base.mjs` 头注即契约）：

```
weight = (quotaFactor + idleBonus + successFactor) × manualWeight
  quotaFactor   = quotaRatio × 10        （null → 借候选集均值，无已知值按 0；不惩罚）
  idleBonus     = min(闲置小时 × 0.5, 5)  （从未用过按 999 小时）
  successFactor = 最近 50 次成功率 × 3
  manualWeight  = clamp(0..20)；0 = 硬过滤
```

- 禁止在池内重写权重、另立成功率窗口（`SUCCESS_WINDOW = 50`）或自定 clamp 范围。
- 公式调整属重决策：影响全部池的流量分配（`A3`）。

## 2. 冷却与熔断：kind 归池，时长归 settings

- **池适配层只回答「上游说了什么」**：把上游错误码映射为冷却 kind（`blocked` / `busy` / `quota` / `server`，见 `zcode/index.mjs` `COOLDOWN` 注释）。
- **kind → 时长的映射只在 `pools/settings.mjs`**（`blockedCooldownMs` 等）。池内引用常量名，不复制毫秒数值——防止两处漂移（`03 §3`）。
- 熔断（`breakerThreshold` / `breakerCooldownMs` / `breakerCapMs`）由 `base.mjs` 状态机执行，池只上报失败，不自判熔断。

## 3. 账号状态由调度器派生

| 状态 | 含义 | 谁决定 |
| --- | --- | --- |
| `ok` | 可正常服务 | 调度器 |
| cooling | 冷却中，`cooldownUntil` 是唯一时间字段 | 调度器（kind 由池上报） |
| `needs_login` | 凭证失效，需重新接入 | 池上报 |
| `disabled` | `enabled: false`，硬过滤 | 用户（面板） |

- 面板只展示派生结果，不自行推算状态；客户端倒计时（`app.js` `cooldownCell`）仅做**展示**，不参与任何「能否服务」判定——这是前端「状态由后端派生」约束（`docs/frontend/08 §4`）的后端镜像。
- 「这个账号现在能不能用」的判据收敛为调度器内部状态机；任何调用点走它，不在端点里重算。

## 4. 设置项

- 优先级：`data/pool-settings.json` 文件优先；环境变量（`ENV_KEYS`）只作**首次默认值**；首次启动把默认值落一份文件。
- 钳制规则集中在 `settings.mjs`：整数类 `MIN_ONE`（≥1）、时长类允许 0（= 不冷却）、布尔类 `BOOLEAN_KEYS`（0/1）、比率类 `FLOAT_MIN`（≥0.0001）。
- **新增设置项四件套**（缺一即闸门失败）：
  1. `DEFAULT_SETTINGS` 加默认值；
  2. `SETTING_KEYS` / `ENV_KEYS` 加键名；
  3. 归入正确的钳制集合（`MIN_ONE` / `BOOLEAN_KEYS` / `FLOAT_MIN`）；
  4. `test/settings.*.test.js` 补钳制断言。
- 面板的单位换算（毫秒 ↔ 分钟/小时/秒、布尔 0/1、汇率原样）按 `panel/public/app.js` `SETTING_FIELDS` 现状；换算方向改变属重决策。

## 5. 落盘纪律

- 写 `data/` 一律 **tmp + rename 原子替换**（`claim-scheduler.mjs` 的 `writeJson` 是范例），禁止直接覆写目标文件（半写状态会损坏密钥库）。
- 权限：目录 `0o700`、文件 `0o600`（`boot.mjs` mkdirSync 先例）。
- `claims.json` 只存结论/积分/错误，**绝不存凭证**；滚动保留上限（500 条）在 `claim-scheduler.mjs` 内维护。
- 每日补领与周末抢领的时间判定统一走北京时间（UTC+8 固定偏移，`beijingNow()`），禁止另建时区逻辑。

## 6. 额度与 claim 语义

- `quotaRatio` 是权重的输入：查询失败/上游未返回按 `null` 处理——**不惩罚、不猜测单个账号的额度**，权重借候选集中已知额度的均值（无任何已知值时按 0，彼此相等）。此规则有专门测试锁定（`test/scheduler.test.js`），调整属重决策（`A3`）。
- claim/checkin 的 `run()` **保证不抛**（`claim-scheduler.mjs` 头注契约）：单账号失败不影响其它账号，失败信息进结果行，不中断整轮。
- credits → tokens 换算只在设置项（`wbCreditTokensRate` 等）一处生效，展示层不再乘系数。
