# 05 · 路由与菜单

> `<端>` 指业务域/角色目录；`stu` / `tech` / `admin` 是示例前缀，新项目按自己的域替换，规则不变。

## 1. 菜单数据源

菜单数据在 `src/api/menu.ts`，是路由注册与侧栏渲染的唯一来源。

| 字段 | 说明 |
| --- | --- |
| `path` | 路由路径，必须带端前缀，首页为各端前缀本身 |
| `name` | 路由名，**必须带端前缀且全局唯一**，见 §1.1 |
| `component` | 相对 `src/view` 的路径，不带 `.vue` |
| `title` | 菜单标题 |
| `icon` | Element Plus 图标名 |
| `order` | 排序 |
| `role` | 可见端/角色，不填表示所有 |
| `group` | 侧栏分组 |
| `hidden` | 只注册路由，不出现在侧栏 |
| `menuPath` | 详情页高亮哪个菜单（带端前缀，如 `stu/courses`） |
| `children` | 二级菜单（模式页侧栏数据源）：父项只做展开/收起，不设 `name` / `component` 时**不注册路由**；`path` 写带 `:id` 的**完整**真实路径，主侧栏不展开这组 children |

- 菜单记录用接口约束（`MenuRecord`）。
- `role` 用联合类型（`'student' | 'teacher' | 'admin'` 之类），避免拼错。
- **菜单里不配强调色**：主色按登录端/角色统一，由 `useRoleAccent` 类 composable 与 `App.vue` 写入 `data-accent`，见 [07-视觉规范](07-视觉规范.md)。
- 二级菜单用 `el-sub-menu` + `el-menu-item` 渲染。

### 1.1 路由名必须显式带端前缀

多端菜单在同一个 `MENUS` 对象里，`name` 只是普通字符串，**不显式区分就会重名互相覆盖**。因此所有 `name` 一律写成 `<端前缀><业务名>`：

| 端 | 前缀 | 示例 |
| --- | --- | --- |
| 学生 | `stu` | `stuHome` / `stuCourses` / `stuQuiz` / `stuQuizRank` |
| 教师 | `tech` | `techHome` / `techMembers` / `techGrading` |
| 管理 | `admin` | `adminHome` / `adminUsers` / `adminArchive` |

- 业务名保持大驼峰，与 `component` 段落对应（`stu/quizzes` → `stuQuizzes`，`stu/quizzes/:pid` → `stuQuiz`）。
- **禁止**依赖「注册时自动改名」这类隐式规则：注册顺序一变，哪个端拿到原名就会变。显式命名后，任何时候用 `router.push({ name: 'stuHome' })` 都是确定的。
- 新增菜单时先搜一遍 `src/api/menu.ts` 确认同名不存在。

## 2. URL 端前缀（硬约束）

| 端 | URL 前缀 | 首页 | 示例 |
| --- | --- | --- | --- |
| 学生 | `/stu` | `/stu` | `/stu/courses`、`/stu/courses/C001/docs`、`/stu/quizzes/QS001/rank` |
| 教师 | `/tech` | `/tech` | `/tech/members`、`/tech/grading` |
| 管理 | `/admin` | `/admin` | `/admin/users`、`/admin/audit` |

- `menu.ts` 每条记录的 `path` 都要写完整前缀；不要写 `''`、`courses` 这类不带端的路径。
- 详情页 / 子页同样带前缀（`stu/courses/:cid/docs` 等）。
- 根路径 `/` 不承载业务页面，由守卫重定向到当前端首页。
- 登录后的跳转、面包屑、`menuPath` 高亮都基于带前缀的路径。

### 公共路由（public）

公共路由是**无需登录、不挂 `DefaultLayout` 壳、不参与动态注册**的页面，与业务路由严格分离：

- **路径白名单**：如 `/login`（登录页）；新增公共页必须先在此登记再实现。
- **代码位置**：`src/view/common/`（登录页 `view/common/login/`，404 页 `view/common/not-found/`）。
- **声明方式**：静态写在 `src/router/index.ts` 顶层 `routes`，并带 `meta: { public: true }`（守卫据此放行；不带该标记的路由一律视为需要登录）。
- **禁止**：公共页使用端前缀路径；业务页放进 `view/common/`；业务路由静态注册。404 页不属公共路由——它挂在布局壳下作为 `fallback` 兜底。

## 3. 动态注册（`src/router/dynamic.ts`）

- 使用 `import.meta.glob('../view/**/*.vue')`。
- 解析顺序：先找 `../view/<component>.vue`，再回退 `../view/<component>/index.vue`。
- 找不到时回退 `common/not-found`，并在控制台警告。
- **路由在 `router/index.ts` 创建时一次性全量注册**（多端菜单都挂上），守卫只负责登录态与端校验。这样地址栏直刷深链不会因为动态注册滞后先落到 `fallback`。
- 多端路由名一律显式带端前缀，不做运行时改名，见 §1.1。跳首页既可用路由名也可用 path。
- `routableMenus` 排序：父级节点在前、children 在后。带参子路由必须排在静态同级路径之后。
- 详情页必须设置 `hidden: true`、`menuPath`、`role`，不出现在侧栏。
- 路由名是页面跳转的唯一依据，迁移目录时不要改路由名。
- `router/index.ts` 在布局壳下留了一条 `fallback` 兜底路由，守卫据此把根路径 `/` 与未注册路径统一送回端首页。
- 切换端/角色后菜单由 `session.loadMenus()` 重新拉取；路由表是全量的，不需要移除重建。

## 4. 跳转方式

- 页面内跳转一律用路由名，不硬编码 URL：

```ts
router.push({ name: 'stuQuiz', params: { pid } })
```

- 带参数的详情页由父页面传参，不在模板里拼字符串路径。
- 进模式页时按 [06 §5.2](06-布局与页面范式.md) 在 query 上带 `from`，供返回按钮解析。
- 返回按钮的语义见 [06-布局与页面范式](06-布局与页面范式.md)，不使用 `router.back()`。

## 5. 新增一个页面

1. 建 `src/view/<端>/<模块>/index.vue`。
2. 在 `src/api/menu.ts` 加一条 `MenuRecord`。
3. 需要详情页就建 `views/` 放路由页，补 `hidden` / `menuPath` / `role`。
4. 需要二级菜单就填 `children`，父项不设 `name` / `component`。
5. 跑 `pnpm typecheck` + `pnpm build`，确认 `dynamic.ts` 能解析 `component`。
