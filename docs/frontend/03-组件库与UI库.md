# 03 · 组件库与 Element Plus

## 1. 总则

**界面元素只要 Element Plus 有对等组件，就必须用 Element Plus，禁止手写等价物。**

优先级从高到低：

1. **Element Plus 组件的 wrapper 封装**（`src/components/el/`，见 §5）——默认选择
2. **`src/components/` 自研业务组件**（仅当 Element Plus 数据模型装不下业务语义，且已在 [09-组件清单](09-组件清单.md) 登记）
3. **原生 HTML**（仅限纯布局容器与语义标签：`div` / `section` / `nav` / `ul` / `dl` 等，不得承载交互控件）

判断口径是「能力」，不是「外观」：如果 `el-table` 能表达这张表，就不允许因为「原生 table 样式更好调」而保留原生 table。

## 2. 强制映射表

| 场景 | 禁止 | 必须使用 |
| --- | --- | --- |
| 数据表格 | `<table class="tbl">` | `el-table` + `el-table-column`，空态用 `#empty` 插槽，行展开用 `type="expand"` |
| 按钮（主/次/小号/禁用） | `<button class="btn">` | `el-button`（`type` / `plain` / `size` / `disabled` / `native-type`） |
| 文字按钮 / 行内链接 | `<span class="link">` | `el-link` 或 `el-button link` |
| 状态标签 / 胶囊 | `<span class="tag">`、`.pill` | `el-tag`（`type` 取 success / info / warning / danger / primary） |
| 空状态 | `<div class="empty">` | `el-empty`（`#empty` 插槽或独立使用） |
| 提示条 | `<div class="note">` | `el-alert`（`:closable="false"`） |
| 进度条 | 手写 `.track` + `.fill` | `el-progress`（标题与百分比用外层 grid 承载） |
| 指标 / 大数字 | 手写 `.bignum`、`.stat .v` | `el-statistic`（走 `ElStatistic` wrapper，见 [09](09-组件清单.md)） |
| 分页 | 手写页码 | `el-pagination`（走 `TablePager`，见 [09](09-组件清单.md)） |
| 时间线 | 手写 `.tl` + `.tl-dot` | `el-timeline` + `el-timeline-item` |
| 折叠 / 展开行 | `expanded` ref + `v-if` 子行 | `el-table` `type="expand"` 或 `el-collapse` |
| 卡片 | 手写 `.panel` | `el-card`（`shadow="hover"` + `#header` 插槽） |
| 侧栏导航 / 页内导航 / 模式导航 | 手写按钮列表 | `el-menu` + `el-menu-item` + `el-sub-menu` + `el-icon` |
| 表单字段 | `.field > label` | `el-form` + `el-form-item` + `el-input` / `el-select` / `el-date-picker` |
| 单选 / 多选 / 开关 | 手写选中态 | `el-radio(-group)` / `el-checkbox(-group)` / `el-switch` |
| 弹窗 / 抽屉 | 自写遮罩 | `el-dialog` / `el-drawer` |
| 悬浮说明 | 原生 `title` 属性 | `el-tooltip` |
| 下拉菜单 | 手写 | `el-dropdown` + `el-dropdown-menu` + `el-dropdown-item` |
| 分页 | 全量渲染 | `el-pagination`（列表超过 20 行时） |
| 描述列表（键值对） | 手写 `dl.kv` | `el-descriptions` + `el-descriptions-item` |
| 分割线 / 徽标 / 骨架屏 | 手写 | `el-divider` / `el-badge` / `el-skeleton` |
| 消息反馈 | 静默跳转或自写 toast | `ElMessage` / `ElMessageBox` / `ElNotification` |
| 加载态 | 自写 loading 文案 | `v-loading` 指令 / `ElLoading` 服务 |
| 步骤条 | 手写 | `el-steps` + `el-step` |
| 面包屑（可点时） | 拼接文本 | `el-breadcrumb` + `el-breadcrumb-item` |

## 3. 图标规范（硬约束）

**禁止用键盘符号、字符、emoji 代替图标。** 所有图标一律来自 `@element-plus/icons-vue`，默认用 `<el-icon>` 包裹（见 §3.2）。

### 3.1 典型替换

| 字符写法 | 必须改为 |
| --- | --- |
| `‹` / `←` | `ArrowLeft` |
| `→` | `ArrowRight` |
| `＋` | `Plus` |
| `×` | `Close` |
| `✓` | `Check` |
| `▶` | `VideoPlay` |

### 3.2 使用方式

```vue
<script setup lang="ts">
import { ArrowLeft, Filter, Plus, Search } from '@element-plus/icons-vue'
</script>

<template>
  <!-- 首选：<el-icon> 包裹（按钮、菜单、独立图标、插槽位一律用这种） -->
  <el-button aria-label="返回"><el-icon><ArrowLeft /></el-icon></el-button>
  <el-button aria-label="筛选条件"><el-icon><Filter /></el-icon></el-button>
  <el-button type="primary"><el-icon><Plus /></el-icon>新对话</el-button>
  <el-input v-model="keyword" placeholder="搜索"><template #prefix><el-icon><Search /></el-icon></template></el-input>
</template>
```

- **合法写法只有两种**：用 `<el-icon>` 包裹图标组件（首选），或用 Element Plus 官方 icon prop（`:icon` / `:prefix-icon` / `:suffix-icon`）传入图标组件引用。
- 禁止裸 `<svg>`、禁止字符（`← → ‹ ＋ × ✓ ▶` 等）、禁止 emoji、禁止第三方图标库。
- 不带文字的图标按钮**必须**有 `aria-label`。
- 图标尺寸跟随 `el-button` / `el-input` / `el-menu` 的 `size`，不单独写死像素。
- 新增依赖禁止：不引入 `@vicons`、iconify 等第三方图标库。

## 4. 允许保留自研的情形

「替换会造成业务语义丢失」这条容易被滥用，本节给出明确判据。

### 4.1 判据

> **长得不像 → 改样式（用 §5 的 wrapper）。数据装不下 → 才自研。**

只要 Element Plus 组件在**行为和数据模型**上能表达业务（哪怕要传一堆 props、要包一层 wrapper、要写 `:deep()`），就**必须用 Element Plus**。

### 4.2 真正允许自研的两种情况

**情况一：Element Plus 没有对等组件。**

- 第三方图表封装（如 `EChart.vue`）
- 顶栏页头上报机制（`PageHead.vue` 的 DOM 抓取 + store 上报）
- 双栏布局壳（`TwoPaneLayout.vue` 的 sticky + 断点降级滚动流）

**情况二：Element Plus 组件的数据模型装不下业务语义。**

判断方法是自问：**「我能不能只靠传 props，把这条业务规则表达出来？」**

| 例子 | 为什么装不下 |
| --- | --- |
| 答题卡方格网 | 业务语义是「题型分组 × 组内序号 × 五种作答态」，`el-button` 网格没有「组内序号」这个概念，五态色也无法通过 `type` 表达（`type` 只有 success/info/warning/danger/primary，且不含「未作答」）。硬套会把业务状态稀释成按钮样式。 |
| 聊天气泡 | 业务语义是「左/右归属 + 引用来源块 + 拒答态」，无对等组件，`el-card` 无法区分消息归属。 |

### 4.3 不算理由

以下都**不是**保留自研的理由：

- 「Element Plus 默认圆角是 4px，不满足设计规范」→ 用 wrapper 改（§5）
- 「el-card 的 header 样式不好调」→ 用 `:deep()` 或 wrapper
- 「原生 table 更容易做合并单元格」→ `el-table` 支持 `span-method`
- 「样式不好写」→ 这条永远不成立

### 4.4 登记要求

任何保留必须写进 [09-组件清单](09-组件清单.md)，并回答：

1. Element Plus 里有没有**行为对等**的组件？
2. 传入哪些 props 也表达不了哪条**业务规则**？
3. 如果将来 Element Plus 提供对等能力，替换成本是多少？

**没有登记的自研 UI 组件视为违规。**

## 5. 样式拦截：`components/el/` wrapper

### 5.1 为什么需要 wrapper

`tokens.scss` 的 CSS 变量只能覆盖颜色，**覆盖不了圆角、边框粗细、内边距、hover 阴影**。当 Element Plus 默认样式不符合 [Design-md.md](Design-md.md) 时，需要一层统一的包装来注入设计 token。

**规则：允许改 Element Plus 的样式，但只能通过 wrapper 全局定义一次，不能在页面里逐个 `:deep()` 打补丁；绝不允许重写 Element Plus 组件本身。**

### 5.2 目录与命名

```
src/components/el/
├─ ElButton.vue      # 圆角 8px、主次态边框 1.5px、padding 10/18
├─ ElCard.vue        # 圆角 12px、padding 24、hover 阴影
├─ ElTag.vue         # 胶囊 999px、语义色映射
├─ ElInput.vue       # 圆角 8px、边框 1.5px、聚焦 2px ring
├─ ElDialog.vue      # 统一圆角与内间距
├─ ElTable.vue       # 表头 13px、行 hover --accent-10
└─ ElEmpty.vue       # 空态居中与配色
```

- 文件名 **PascalCase**，与 `element-plus` 组件同名（`ElButton.vue` 对应 `el-button`）。
- 组件内 `name` 与文件名一致，便于 Devtools 区分；**但不得与 EP 注册名同名**（自递归白屏，见 [09 §1.1](09-组件清单.md)）。

### 5.3 wrapper 的职责边界

wrapper **只做样式注入**，不写业务逻辑：

```vue
<!-- src/components/el/ElButton.vue -->
<template>
  <el-button v-bind="$attrs" :class="['el_button', `el_button--${type}`, $attrs.class as string | undefined]">
    <slot />
  </el-button>
</template>

<script setup lang="ts">
interface Props {
  type?: 'primary' | 'default' | 'danger'
}
const props = withDefaults(defineProps<Props>(), { type: 'default' })
</script>

<style scoped lang="scss">
.el_button {
  border-radius: var(--radius-sm);
  padding: 10px 18px;

  &--primary {
    background: var(--accent);
    border-color: var(--accent);
  }
}
</style>
```

约束：

- `v-bind="$attrs"` 透传所有 props 与事件，wrapper 不新增业务 props。
- 不覆盖 Element Plus 的事件、插槽、生命周期行为。
- 不 fork 组件源码，不改 `element-plus/dist/index.css`。
- `ElMessage` / `ElMessageBox` / `ElNotification` / `v-loading` 这类**服务式 API** 直接使用 Element Plus 原版，不做 wrapper。

### 5.4 import 约束

- 页面与业务组件**只能**从 `@/components/el/` 引入模板组件，**禁止** `import { ElButton } from 'element-plus'`。
- `main.ts` 保持 Element Plus 全量注册（wrapper 内部可以直接用 `el-button` 标签）。
- 服务式 API（`ElMessage` 等）豁免此约束。

### 5.5 什么时候加新 wrapper

只有当**至少两个页面**都遇到同一个 Element Plus 视觉偏差时才加 wrapper。单页面特例仍在组件作用域内用 `:deep()` 处理，并在变更说明中写明原因。

### 5.6 wrapper 必须合并 `$attrs.class`（硬约束）

调用方写 `<ElCard class="xxx">` 时，这个 `class` 会随 `$attrs` 透传到内部 EP 组件上，**覆盖 wrapper 自己的 `class`**，导致 wrapper 的整套样式规则静默失效。

```vue
<!-- ❌ 错误：调用方传 class 时 .el_card 规则整体失效 -->
<el-card v-bind="$attrs" class="el_card">

<!-- ✅ 正确：显式合并，两个 class 都保留 -->
<el-card v-bind="$attrs" :class="['el_card', $attrs.class as string | undefined]">
```

同理适用于所有 wrapper（`ElButton` / `ElInput` / `ElTable` / `ElTag` / `ElEmpty` / `ElDialog` / `ElStatistic`）。

**为什么这条是硬约束**：不合并时，调用方传一个 `class` 就会让 wrapper 的圆角、内边距、页头底色全部失效，且表现为「某个页面的样式问题」，排查成本极高。

### 5.7 `<style scoped>` 的样式边界

- wrapper 内的 `:deep(.el-xxx__yyy)` 只能改 EP 内部结构；wrapper 根元素的样式直接写类名即可。
- 组件拆分时，**父组件 scoped style 里的类名子组件拿不到**，对应样式必须随组件一起下沉。

## 6. 主题覆盖规则

- `src/styles/tokens.scss` 按 `data-accent` 覆写整套 `--el-color-primary*`，Element Plus 主色跟随**端/角色主色**，不需要页面单独设置（机制见 [07-视觉规范](07-视觉规范.md)）。
- 设计 token 优先在 wrapper 里用 CSS 变量绑定，不要在页面里写死数值。
- 页面内仍有不可避免的特例时，只用 `:deep()`，且限定在组件作用域：

```vue
<style scoped lang="scss">
.my_table {
  :deep(.el-table__header th) {
    font-weight: 500;
  }
}
</style>
```

- **禁止**修改 `element-plus/dist/index.css`。
- **禁止**用 `!important` 强行压 Element Plus 样式，先确认是不是 CSS 变量或 wrapper 能解决。

## 7. 组件使用要点

### 7.1 `el-table`

- 列宽用 `el-table-column` 的 `width` / `min-width`，不用内联 `style="width:300px"`。
- 数字列用 `align="right"`，次要文字列用 `class-name`。
- 空数据交给 `#empty` 插槽，不要手动拼 `<tr><td colspan>`。

### 7.2 `el-button`

- 主操作 `type="primary"`，次要操作不写 `type`，危险操作 `type="danger"`。
- 小尺寸用 `size="small"`，胶囊用 `round`。
- 行内文字按钮用 `link`，不要用 `plain` 冒充。
- 图标统一走 `:icon`，见 §3。

### 7.3 `el-tag`

- 状态 → 类型映射集中在组件里维护，不要在每个页面重复写。

### 7.4 `el-menu`

- 主侧栏、页内左栏、模式侧栏全部用 `el-menu`，保持行式同构（见 [06-布局与页面范式](06-布局与页面范式.md)）。
- 菜单项图标用 `<el-icon>` 插槽。

### 7.5 反馈组件

- 成功/失败提示用 `ElMessage`，不要自写 toast。
- 二次确认用 `ElMessageBox.confirm`。
- 重要通知用 `ElNotification`。

## 8. 新增组件的判定流程

```
需要一个新的界面元素
  ├─ 查 Element Plus 文档 → 有对等组件？
  │    ├─ 有 → 用 wrapper（components/el/），禁止自研
  │    └─ 没有 ↓
  ├─ 查 09-组件清单 → 是否已有自研封装？
  │    ├─ 有 → 复用，不重复造
  │    └─ 没有 ↓
  └─ 按 §4.2 判据确认「数据模型装不下」，自研并登记
```

**造组件之前必做的两件事：**

1. **先查同模块 `components/`**：当前模块是否已经有近似实现？有就把公用的部分提出来，不要复制一份改改。
2. **再查 `src/components/`**：跨模块是否已有？有就提升复用。
