# 02 · 目录与文件组织

> `<端>` 指业务域/角色目录（如 `stu` / `tech` / `admin`），按项目实际域替换；单端项目可省去这一层。

## 1. `src/` 结构

```
src/
├─ api/                  # 接口与菜单数据（*.ts），页面不直接调 axios
├─ components/
│  ├─ el/                # Element Plus wrapper（样式拦截层，见 03 §5）
│  ├─ layout/            # 布局壳块：AppSidebar / AppTopbar / PageHead / TwoPaneLayout
│  ├─ data/              # 数据展示类：MetricRow / EntityHead / StatusTag / TablePager
│  └─ common/            # 通用交互：SegSwitch / EChart / ModulePlaceholder
├─ composables/          # 跨模块复用的 composable
├─ layout/               # 布局壳入口
│  └─ DefaultLayout.vue  # 只做组装，不放业务
├─ mock/                 # 演示数据（按端拆文件）
├─ router/               # index.ts / dynamic.ts / guard.ts
├─ store/                # 运行态（按职责拆文件）
├─ styles/               # tokens.scss / global.scss / 端级结构样式
├─ types/                # 跨文件复用类型
├─ main.ts
└─ view/
   ├─ common/
   │  ├─ login/index.vue
   │  └─ not-found/index.vue
   └─ <端>/              # 各业务域（URL 前缀 /stu、/tech、/admin 等）
```

## 2. 多页面模块的目录约定

一个模块只要有 **`index.vue` 之外的路由页**（详情页、模式页），就按下面的结构组织：

```
view/<端>/<模块>/
├─ index.vue          # 列表页（菜单可直达）
├─ views/             # 其余路由页：模式页、详情页、子视图
├─ components/        # 本模块私有组件
└─ composables/       # 本模块私有 composable
```

- **`index.vue` 之外的路由页一律放 `views/`**，不平铺在模块根目录。
- 只有单个 `index.vue` 的简单模块（如 `home`）不需要建 `views/`。
- `components/` 与 `composables/` 只有实际用到时才建，不预先创建空目录。
- 模块内引用也一律写 `@/view/<端>/<模块>/components/Xxx.vue` 或 `@/composables/useXxx`，**禁止 `./` 与 `../`**（见 [04 §2](04-SFC与代码规范.md)）。

## 3. 命名规范

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| Vue 组件文件 | **大驼峰 PascalCase** | `SheetNav.vue`、`AppSidebar.vue`、`ElButton.vue` |
| TS 文件（普通模块） | 小驼峰 camelCase | `request.ts`、`useQuizBar.ts` |
| 目录 | 小写单词或 kebab-case | `components/`、`quizzes/`、`not-found/` |
| 固定目录名 | `views/` / `components/` / `composables/` | 不写 `Views/`、`composable/` |
| 路由页固定文件名 | `index.vue`（列表）/ 语义化名（`overview.vue`、`rank.vue`） | `<端>/quizzes/views/rank.vue` |
| **CSS 类名** | **蛇形 snake_case** | `.answer_sheet`、`.app_topbar`、`.sheet_cell` |
| CSS 修饰符 | `block--modifier` / `block_element` | `.answer_sheet--ok` |
| TS 变量 / 函数 | 小驼峰 camelCase | `cellState()` |
| 常量 | 全大写下划线 | `TYPENAME`、`REFUSE` |
| 类型 / 接口 | 大驼峰 PascalCase | `MenuRecord`、`QuestionScore` |

补充约定：

- 组件内部 `defineOptions({ name: 'XxxYyy' })` 与文件名保持一致。
- SFC 文件名一律 PascalCase，禁止 kebab-case（如 `quiz-nav.vue`）。
- CSS 类名一律 snake_case，禁止 kebab-case（如 `.sheet-cell`）。

## 4. 页面长度与拆分

### 4.1 长度约束

**页面软上限 200 行**，统计口径为模板 + 脚本 + 样式总行数。

| 类型 | 建议上限 |
| --- | --- |
| 路由页（`index.vue` / `views/*.vue`） | 200 行 |
| 业务组件（`components/Xxx.vue`） | 150 行 |
| composable（`useXxx.ts`） | 120 行 |

数字是软上限：超过不代表一定错，但必须说明「为什么不能再拆」。**默认动作是拆，不是解释。**

### 4.2 拆分优先级

1. **样式块优先**：`<style>` 超过 80 行就先抽出去。
2. **可复用视图块**：一个区块在别处也可能用到 → 抽到模块 `components/`。
3. **独立交互块**：自带状态的小区域（弹窗、卡片、表单）→ 抽成组件。
4. **逻辑**：派生计算、状态机 → 抽成 `composables/useXxx.ts`。

### 4.3 拆分的两条禁令

- **不许抽「只包一层的转发组件」**：新组件只是把 props 原样传给内部，没有自己的模板结构或逻辑，就不要抽。
- **不许把逻辑搬进 `.ts` 里拼 HTML**：拆出的是 SFC，不是模板字符串。

### 4.4 拆分后的命名与样式

- 子组件放 `<模块>/components/`，文件名 PascalCase，按**业务域**命名而不是按位置命名：
  - 好：`SheetNav.vue`（答题卡左栏）、`QuestionCard.vue`（单题作答卡）、`SubmitDialog.vue`（提交确认）
  - 坏：`LeftPanel.vue`、`TopBar2.vue`、`ItemWrapper.vue`
- composable 命名 `useXxx.ts`，导出 `useXxx()`。
- **拆出的组件必须接收自己的样式**：父组件 scoped 里的类名子组件拿不到，拆分时要把对应样式一起下沉，否则样式静默失效。

## 5. 组件放置规则

按「复用范围」分五层，从上到下复用范围递减：

| 目录 | 放什么 | 示例 |
| --- | --- | --- |
| `src/components/el/` | Element Plus wrapper，只注入设计 token | `ElCard`、`ElTable`、`ElStatistic` |
| `src/components/layout/` | 布局壳块 | `AppSidebar`、`AppTopbar`、`PageHead`、`TwoPaneLayout` |
| `src/components/data/` | 数据展示类业务组件 | `MetricRow`、`EntityHead`、`StatusTag`、`TablePager` |
| `src/components/common/` | 通用交互组件 | `SegSwitch`、`EChart`、`ModulePlaceholder` |
| `view/<端>/<模块>/components/` | 模块私有组件 | `MistakeCard`、`CourseNav` |

- 跨模块复用的 composable 放 `src/composables/`，模块私有的放 `view/<模块>/composables/`。
- **新建组件之前先查同模块和 `src/components/` 有没有已实现的近似组件**，有就提取复用，不许复制一份改改。
- 同一个视觉结构第二次出现时就必须提取，不许「先复制、以后再说」。
- 脚本扩展名只允许 `.ts`，样式只允许 `.scss`；同一目录不要混放 `.js` 与 `.ts`、`.css` 与 `.scss`。

## 6. 数据文件放置

- 演示数据集中放 `src/mock/`，**按端拆文件**（`student.ts` / `teacher.ts` / `admin.ts`），不把多端数据堆进同一个文件。
- 运行态在 `src/store/`，按职责拆（登录态 / 各业务域 / 顶栏信息条等），文件内注释写明职责。
- 跨文件复用的类型放 `src/types/`，单文件内部类型可以写在文件内并导出。
- 实体依据见 `docs/frontend/entities/`，不新增原型与实体文档都没有的业务字段。

## 7. 样式文件放置

| 文件 | 职责 |
| --- | --- |
| `src/styles/tokens.scss` | 设计变量：颜色、圆角、间距、字体、阴影、`--el-color-primary*` 联动 |
| `src/styles/global.scss` | 全局重置、`html/body`、通用基础样式 |
| `src/styles/<端>.scss` | 跨页面复用的结构类（仅保留 Element Plus 无对等能力的部分） |

- 组件样式一律写在 SFC 的 `<style scoped lang="scss">` 里。
- Element Plus 视觉偏差优先在 `components/el/` wrapper 里统一解决（见 [03 §5](03-组件库与UI库.md)）。
- **组件专用的样式不要留在全局 scss**：全局文件只放真正跨页面的结构类；某个组件的样式搬进组件后，全局里的同名类必须删除。
- UI 库替代后失效的结构类必须删除，不许留死代码。
- 共享 mixin / function 放 `src/styles/_mixins.scss`、`src/styles/_functions.scss`，用 `@use '@/styles/mixins' as *;` 引入；**禁止 `@import`**（已废弃）。

## 8. 新增模块的完整步骤

1. 在 `src/view/<端>/<模块>/index.vue` 建列表页。
2. 有详情页 / 模式页时，建 `views/` 子目录放其余路由页。
3. 在 `src/api/menu.ts` 加 `MenuRecord`：`path` 带端前缀、`name` 写成 `<端前缀><业务名>`（如 `stuGrades`）、`component` 是相对 `src/view` 的路径**且必须与新目录一致**。
4. 路由页一律设 `hidden: true`、`menuPath`、`role`（强调色不在这里配，按端统一）。
5. 需要私有组件就建 `<模块>/components/`，先查有没有可复用的。
6. 需要 composable 就建 `<模块>/composables/`；跨模块复用则放 `src/composables/`。
7. 需要数据就在 `src/mock/*.ts` 加，派生逻辑放 `src/store/*.ts`。
8. 页面超过 200 行按 §4 拆分。
9. 跑 `pnpm typecheck` + `pnpm build`。
