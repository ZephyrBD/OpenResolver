# 09 · 组件清单

`src/components/` 分四层 + 模块私有层：

| 目录 | 内容 | 规则 |
| --- | --- | --- |
| `components/el/` | Element Plus wrapper（样式拦截） | 只注入设计 token，不写业务 |
| `components/layout/` | 布局壳通用块 | 跨端复用 |
| `components/data/` | 数据展示类业务组件 | 跨模块复用，登记在本清单 |
| `components/common/` | 通用交互组件 | 跨模块复用，登记在本清单 |
| `view/<端>/<模块>/components/` | 模块私有组件 | 不进本清单 |

`components/` 下的自研组件**未登记视为违规**。新项目接入时按实际情况填写下表；本文保留通用 wrapper 规则与推荐的通用组件。

## 1. Element Plus wrapper（`components/el/`）

文件命名与 EP 组件同名，PascalCase。推荐的起点清单：

| 文件 | 目标组件 | 注入的设计 token |
| --- | --- | --- |
| `ElButton.vue` | `el-button` | 圆角 8px、主次态边框 1.5px、padding 10/18、hover 不缩放 |
| `ElCard.vue` | `el-card` | 圆角 12px、padding 24、hover 阴影 `--shadow-card`、页头 accent 底 |
| `ElTag.vue` | `el-tag` | 胶囊 999px、语义色映射 |
| `ElInput.vue` | `el-input` | 圆角 8px、边框 1.5px、聚焦 2px ring |
| `ElDialog.vue` | `el-dialog` | 统一圆角与内间距 |
| `ElTable.vue` | `el-table` | 表头 13px、行 hover `--accent-10`、圆角 12px |
| `ElEmpty.vue` | `el-empty` | 空态居中与配色 |
| `ElStatistic.vue` | `el-statistic` | 大数字样式（字号 / 字距 / 单位继承正文色） |

- wrapper 只做样式注入，`v-bind="$attrs"` 透传 props/事件，不覆盖行为。
- 两个以上页面遇到同一视觉偏差才加 wrapper；单页特例用 `:deep()`。
- 服务式 API（`ElMessage` / `ElMessageBox` / `ElNotification` / `v-loading`）直接用原版，不做 wrapper。

### 1.1 命名硬约束：组件 `name` 不得与 EP 注册名同名

**wrapper 组件的 `name` 必须与被包装的 Element Plus 组件注册名不同**：

- 文件名保持 `El*.vue`（如 `ElButton.vue`），但 `defineOptions({ name })` 一律使用 **`Ep*` 前缀**（`EpButton`、`EpInput`…），并保留 `inheritAttrs: false`。
- **原因**：wrapper 模板内部要写被包装组件的 kebab 标签（如 `ElInput.vue` 里写 `<el-input>`）。若组件自身 `name` 与 EP 注册名相同（`ElInput`），运行时组件解析会把内部 `<el-input>` 解析成 wrapper 自己，无限递归渲染，抛 `RangeError: Maximum call stack size exceeded`，整页白屏。
- **禁止**把 wrapper 注册为全局组件（`app.component`），否则同样形成自引用。

### 1.2 类名必须合并 `$attrs.class`

所有 wrapper 都要这样写，否则调用方传 `class` 时 wrapper 的样式规则整体失效：

```vue
<el-card v-bind="$attrs" :class="['el_card', $attrs.class as string | undefined]">
```

详见 [03 §5.6](03-组件库与UI库.md)。

## 2. 布局层（`components/layout/`）

推荐清单：

| 文件 | 职责 |
| --- | --- |
| `AppSidebar.vue` | 主侧栏：`el-menu` + 分组 + 端菜单；模式页时替换为模式侧栏 |
| `AppTopbar.vue` | 顶栏：返回按钮 + 端标签 + 页头/实体信息条 + 退出 |
| `PageHead.vue` | 向顶栏上报页面标题与面包屑（渲染到隐藏的上报容器） |
| `TwoPaneLayout.vue` | 左 sticky 导航 + 右内容双栏壳；1080px 以下转横向滚动条带；`#nav-top` 插槽渲染在左栏卡片之外、卡片上方，传入时整列一起吸顶 |

`layout/DefaultLayout.vue` 只做组装，用 `MODE_BY_ROUTE` 按路由名决定是否进入模式页。

## 3. 数据展示层（`components/data/`）

保留理由统一按 [03 §4.2](03-组件库与UI库.md)：**EP 数据模型装不下业务语义**，不是样式问题。推荐的通用组件：

### `MetricRow.vue`

- **职责**：指标卡行（大数字 + 单位 + 说明），多页面共用的统计展示。
- **接口**：`items: MetricItem[]`（`k` / `v` / `unit?` / `sub?`）、`accents?: Accent[]`。
- **机制**：`el-row` + `el-col`（`xs=24 / sm=12 / md=6`）布局，内部用 `ElStatistic`；颜色按 `accents[i % accents.length]` 分配 —— **多了循环，少了忽略**。
- **默认配色**：五色轮换常量（如 `['green', 'orange', 'purple', 'red', 'blue']`），每个页面显式传入，颜色顺序属于页面决策。指标卡属于内容层，**不跟端主色**。
- **为什么 EP 不行**：`el-statistic` 只管单个数字；`el-row` 只管栅格。业务需要「一组指标 + 按顺序分配品牌色 + 说明行」的组合，EP 无对等能力。

### `EntityHead.vue`

- **职责**：实体页头（标题 + 编号徽标 + 元信息 + 右侧状态标签/操作）。
- **接口**：`title`、`badge?`、`meta?`、`status?`；插槽 `#tags`（覆盖默认状态标签）、`#actions`。
- **不吃颜色 prop**：状态色由状态 → `ElTag type` 固定映射。
- **为什么 EP 不行**：需要「标题 + 徽标 + 元信息 + 状态胶囊」的固定排版，`el-descriptions` / `el-page-header` 都不表达这个组合。

### `StatusTag.vue`

- **职责**：状态文案 → 语义色的集中映射。
- **机制**：`Record<string, string>` 映射表集中维护。
- **为什么 EP 不行**：映射表是**业务资产**（多种状态 → 4 个语义色），避免多个调用点各写一套。内部用 `ElTag` wrapper。

### `SheetHead.vue`

- **职责**：右栏顶部行 —— 分类名 + 计数在左，工具区靠最右；整行吸顶，不随页面滚动。
- **接口**：`title`、`meta?`（计数文案，空则不渲染）；插槽 `#tools`。
- **吸顶**：`position: sticky` + `top: 88px`（顶栏 64px + 24px 呼吸位）。背景用 `::before` 伪元素承担：向上盖住间距带、左右各出血 16px（可用变量覆盖），滚动内容不会从缝隙里透出来。
- **≤1080px**：工具区 `flex: 1 1 100%` 换行占满整行。
- **计数来源**：文案由页面 composable 统一产出（`activeMeta`），组件只负责渲染。
- **为什么 EP 不行**：需要「分类标题 + 进度计数 + 右侧工具槽 + 吸顶出血背景」的固定组合，`el-page-header` / `el-affix` 都不表达。

### `TablePager.vue`

- **职责**：列表页统一分页条。
- **接口**：`page`、`pageSize`、`total`；`emit('update:page')` / `emit('update:pageSize')`。
- **机制**：`el-pagination`，`layout="total, sizes, prev, pager, next"`，每页 10 / 20 / 50；`total = 0` 时不渲染。
- **为什么 EP 不行**：EP 有能力，这里只是**统一配置**（布局、页长选项、右对齐）避免多处各写一遍；不新增交互能力。
- **配套**：`src/composables/usePager.ts` 提供本地分页逻辑。

业务专属组件（如 `QuestionCard` 单题卡）按同样格式登记：职责 / 接口 / 状态机 / 「为什么 EP 不行」。

## 4. 通用交互层（`components/common/`）

### `SegSwitch.vue`

- **职责**：iOS 风格长条胶囊滑块分段开关，2–4 段。
- **接口**：`items: { key: string; label: string }[]`、`modelValue: string`、`ariaLabel?: string`；`emit('update:modelValue', value: string)`。
- **使用范围**：**仅列表页**的互斥分类切换。
- **禁止用于模式页内部的视图切换**：模式页的视图由左侧导航承担。
- **为什么 EP 不行**：`el-radio-group` / `el-tabs` 是选项组与页签模型，没有等宽分段胶囊 + 滑块位移这一层交互语义。

### `EChart.vue`

- **职责**：ECharts 实例封装。
- **接口**：`option: EChartsOption`、`height?: number`（默认 300）。
- **约束**：按需注册，只注册实际用到的组件。

### `ModulePlaceholder.vue`

- **职责**：未实现模块的占位页。统一文案 + 顶栏上报的组合，内部用 `ElEmpty`。

### `SheetNav.vue` / `SheetGrid.vue`（答题卡类页面）

- **职责**：左栏外壳（总览计数 → 分类菜单 → 方格网）+ 方格网与图例。
- **约束**：不读 store / route，计数口径、行文案与格子状态全部由调用方算好。
- **为什么 EP 不行**：计数块与方格网（格号 = 分类内序号、按状态着色）是业务语义组合，`el-menu` 只管切换。

### `SideNavPanel.vue`

- **职责**：页面左侧选择导航的通用容器——桌面端（>768px）左 sticky 侧栏列 + 主内容双栏，手机端（≤768px）「≡」按钮 + 悬浮面板 + 遮罩，路由跳转自动收起。
- **接口**：`label: string`（手机端按钮文案）、`navWidth?: string`（默认 260px）；插槽 `#nav` + 默认插槽。
- **为什么 EP 不行**：`el-aside` / `el-drawer` 不表达「桌面常驻侧栏、手机悬浮菜单」的响应式容器语义。

## 5. 模块内组件（`view/<模块>/components/`）

只登记承担固定业务组合的组件；纯版式拆分不登记。登记格式同上：职责 / 接口 / 机制 / 「为什么 EP 不行」。

## 6. 跨模块 composable（`src/composables/`）

| 文件 | 职责 | 接口（示例） |
| --- | --- | --- |
| `usePager.ts` | 本地分页 | `usePager(list: () => T[], defaultSize = 10)` → `{ page, pageSize, total, rows }` |
| `useReturnTo.ts` | 模式页返回来源解析 | `resolveReturnTarget(from, params, fallback)` → `ReturnTarget` |
| `useRoleAccent.ts` | 按端/角色写入 `data-accent` 主色 | 无参数，副作用挂 `documentElement` |

模块私有 composable 放 `view/<模块>/composables/`，不在此登记。

## 7. 禁止的替代写法

以下写法一律用对应的已登记组件或 Element Plus 替代，不要自起炉灶：

| 不要写 | 用 |
| --- | --- |
| 手写指标卡 / 大数字 | `MetricRow` + `ElStatistic` |
| 手写实体页头 | `EntityHead` |
| 手写状态色映射 | `StatusTag` |
| 手写页码 | `TablePager` + `usePager` |
| 手写胶囊分段 | `SegSwitch` |
| 手写答题卡左栏 / 方格网 | `SheetNav` + `SheetGrid` |
| 手写返回按钮 | `AppTopbar` 的模式页返回 |
| 手写导航菜单 | `el-menu` + `el-menu-item` |
| 手写面板卡 | `ElCard` wrapper |

## 8. 新增组件前必做

1. **查 `components/el/`**：是不是只要改样式？是就用 wrapper。
2. **查 `components/data/` / `components/common/`**：有没有近似实现？有就提取公用部分，不复制。
3. **查同模块 `components/`**：模块私有场景是否已有？
4. **按 [03 §4.2](03-组件库与UI库.md) 判据**确认「EP 数据模型装不下」，回答三个问题后才能新建：
   - EP 里有没有**行为对等**的组件？
   - 传入哪些 props 也表达不了哪条**业务规则**？
   - 将来 EP 提供对等能力时的替换成本？
5. 新建后**立即在本清单登记**，写清职责、接口、「为什么 EP 不行」。
